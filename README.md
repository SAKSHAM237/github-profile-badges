## Overview

GitHub Achievements (profile badges) were introduced in 2021 following the NASA Ingenuity Mars Helicopter mission. They display on public GitHub profiles to reflect specific milestones across repositories, pull requests, sponsorships, and discussions.

* **Total Badges:** 11 (7 active, 2 unreleased, 2 retired).
* **Tiered Progression:** Select badges scale across Base, Bronze (`x2`), Silver (`x3`), and Gold (`x4`) tiers.
* **Visibility Requirement:** Activity in private repositories does not count by default. Enable **Include private contributions on my profile** under Profile Settings if you want private repository events to register.

## Earning Walkthroughs

### 1. Quickdraw
Close an Issue or Pull Request within 5 minutes of creation.
1. Open any public repository you own.
2. Navigate to **Issues** > **New issue**, enter a title, and submit.
3. Click **Close issue** immediately.

*Note: Can be completed solo on your own repository using either an Issue or a Pull Request.*

### 2. Public Sponsor
Sponsor any developer or organization through GitHub Sponsors.
1. Visit a profile or repository with GitHub Sponsors enabled.
2. Click **Sponsor** and select a one-time or monthly tier (minimum $1).
3. Complete checkout with **Public** visibility selected (private sponsorships do not trigger the public badge).

*Note: The badge remains permanent even after a one-time sponsorship or canceled monthly tier.*

### 3. Pull Shark
Have 2 Pull Requests merged.
1. Clone a public repository and create a new branch:
   ```bash
   git checkout -b fix/update-docs
   ```
2. Commit a change and push the branch:
   ```bash
   git commit -am "Update documentation"
   git push origin fix/update-docs
   ```
3. Open a Pull Request on GitHub and merge it into the base branch.
4. Repeat once more for a total of 2 merged Pull Requests.

*Note: Closed, unmerged Pull Requests do not count.*

### 4. YOLO
Merge a Pull Request with a requested reviewer before they submit an approval.
1. Ensure a collaborator has access to the repository (and branch protection does not block unreviewed merges).
2. Open a Pull Request from a feature branch.
3. Assign the collaborator under **Reviewers** on the right sidebar.
4. Click **Merge pull request** immediately without waiting for their review.

*Note: Awarded to the user who executes the merge.*

### 5. Galaxy Brain
Have 2 Discussion replies marked as the accepted answer.
1. Locate active public repositories in your domain that use the **Discussions** tab (specifically Q&A categories).
2. Provide complete, accurate solutions to open questions.
3. Have the original author or a maintainer mark your response as **Answer**.
4. Repeat for a second accepted answer.

*Note: Self-marked answers on your own questions and answers in `github.com/orgs/community` do not qualify.*

### 6. Pair Extraordinaire
Co-author a commit inside a merged Pull Request.
1. Create a branch and stage a modification.
2. Include the `Co-authored-by` trailer at the very end of your commit message (preceded by a blank line):
   ```bash
   git commit -m "Refactor parser logic

   Co-authored-by: Collaborator Name <user@example.com>"
   ```
3. Push the branch, open a Pull Request, and merge it.

*Note: The email address must match the co-author's verified GitHub account email (or their `noreply.github.com` address). Both the author and co-author receive progress.*

### 7. Starstruck
Reach 16 stars on a single public repository you personally own.
1. Publish a well-documented tool, library, template, or technical reference.
2. Add clear repository **Topics**, a concise `README.md`, and usage examples or screenshots.
3. Pin the repository to your GitHub profile and share it in relevant technical communities (Hacker News, Reddit, Dev.to, X).

*Note: Repositories owned by a GitHub Organization do not count toward personal Starstruck progress.*

## Visibility and Customization

### Managing Profile Display
* **Disable all badges:** Go to [Profile Settings](https://github.com/settings/profile), scroll to **Achievements**, and uncheck **Show Achievements on my profile**.
* **Hide specific badges:** Open your profile, click the badge under **Achievements**, and toggle visibility off via the menu icon. Hiding a badge does not revoke progress.

### Skin Tone Settings
**Starstruck** and **Quickdraw** adapt to your preferred emoji skin tone. Configure this at [Appearance Settings](https://github.com/settings/appearance) under **Emoji skin tone preference**.

## Troubleshooting

* **Sync Latency:** Background jobs can take up to 24–48 hours to award a badge during high platform load.
* **Private Repositories:** Verify that **Include private contributions on my profile** is checked in settings; otherwise, only public events register.
* **Unmerged Fork Activity:** Commits, issues, or PRs confined entirely inside a fork do not count unless merged upstream.
* **Organization Ownership:** Stars on organization-owned repositories do not count toward **Starstruck**.
* **Stuck Tier Display:** If a tier fails to update, open the badge on your profile, toggle visibility **off**, wait 10 seconds, and toggle it back **on** to force a cache refresh. If unresolved after 48 hours, contact [GitHub Support](https://support.github.com).

## FAQ

**Do badges expire if repository activity stops?**  
No. Unlocked achievements are permanently tied to your account, even if the originating repository is later deleted.

**Do draft Pull Requests count toward Pull Shark?**  
Only once marked ready for review and merged. Closed or unmerged drafts are ignored.

**Does closing my own Issue count for Quickdraw?**  
Yes. Opening and closing an issue on your own public repository within 5 minutes triggers the badge.

**Can I mark my own reply as the answer for Galaxy Brain?**  
No. Self-accepted answers are excluded from progression.

**Can two users unlock Pair Extraordinaire from a single PR?**  
Yes, provided one user authors/merges the commit and the second is properly attributed via the `Co-authored-by:` commit trailer, and the PR is not self-co-authored.
